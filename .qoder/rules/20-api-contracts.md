# Provider 与 API 契约

适用范围：`lumen/providers/*.py`、`lumen/agents/*.py`、`lumen/orchestrator.py`、`lumen/budget.py` 和相应测试。

## 统一边界

1. Agent 只依赖仓库内的数据契约和 Provider 接口，不直接拼接 HTTP 请求。
2. Provider 接受和返回类型化对象；外部 JSON 必须在边界处校验并转换。
3. 凭据仅从环境变量读取。缺少凭据时应快速、清晰地失败，但错误和日志不得包含凭据值或认证头。
4. 所有网络请求必须设置超时；异步任务必须有有限轮询间隔、总超时和明确的终止状态。
5. 可重试错误与不可重试错误必须区分。重试次数有限，并写入运行账本。
6. `--dry-run` 使用纯本地估算器和模拟 Provider，任何路径都不能退化为真实请求。

## 数据契约

- `Shot` 是镜头意图的唯一结构化来源，至少携带镜头 ID、时长、景别、运镜、锚点、角色、场景、导演意图、prompt 种子和声音设计。
- `ShotResult` 必须记录镜头 ID、素材路径、尝试次数、分数、审片意见、成本和是否通过。
- 可变默认值必须使用 `default_factory`，不得共享列表实例。
- `shot.intent` 是审片标准，不得在 Provider 中被丢弃。

## LLM / VLM

- 文本模型返回严格 JSON。解析失败时可将错误回灌并修复一次；再次失败则抛出异常。
- 结构化结果在进入下一 Agent 前必须经过 Pydantic 校验。
- 审片模型接收镜头意图、景别、运镜、角色锚点描述和从成片均匀抽取的三帧。
- 审片维度为：角色一致性、构图符合分镜、光线氛围、无明显崩坏。任一维度低于 6 分或总分低于 7.0 即不通过。
- 不通过结果必须包含具体、可执行的 `critique` 和 `fix_hint`。

## 视频生成

- 视频生成是异步两步式：提交任务取得任务 ID，再轮询至成功、失败或超时。
- 每次提交前用分辨率与时长估算费用并执行 `Budget.check()`；只有任务成功并取得可用结果后才执行 `Budget.charge()`。
- `wan3.x` 参考媒体使用 `input.media` 对象数组；`wan2.x` 图生视频使用 `input.img_url` 字符串。两类字段不得混用。
- `reference_*` 类型与 `first_frame` / `last_frame` 类型互斥，不得在同一请求中组合。
- 本项目默认以 Base64 Data URL 传递本地锚点图，不依赖 OSS 或自建图床。
- 参考图进入 Provider 前必须验证格式、尺寸、长宽比和文件大小；带透明通道的图片先压平并转换为 RGB。
- 任务 ID、状态和服务端错误可以记录；认证头、凭据、完整 Base64 媒体不得写入日志。

## 声音与本地工具

- TTS、音乐和音效 Provider 遵循同样的凭据、超时、日志和预算边界。
- ffmpeg 通过参数数组调用，不拼接 shell 字符串；检查退出码并保留可诊断的脱敏错误。
- 临时文件使用受控临时目录并在读取后清理；不得覆盖源素材。

## 计费与审计

每条外部调用记录至少包含：时间、运行 ID、Agent、镜头 ID（如适用）、Provider、模型、尝试序号、耗时、估算或实际成本、状态和脱敏错误摘要。

价格不是常量真理。实现应将价格表集中配置，并在批量生成前根据官方最新信息校验；价格变更不应要求修改 Agent 逻辑。
