# LUMEN 项目铁律

适用范围：整个仓库。本文应配置为“始终生效”。

## 这个项目是什么

LUMEN 是一个多 Agent 电影生产系统。八个 Agent 分别扮演制片、编剧、分镜、美术、摄影、声音、剪辑和审片。系统通过 `lumen/contracts.py` 中的 Pydantic 模型通信，不通过无约束的裸 `dict`。

`film.yaml` 是电影的源代码；生成的脚本、分镜、锚点、片段、声音、成片和运行账本都是可追溯的派生产物。

## 不可违反

1. 任何会产生费用的外部调用，尤其是视频和图像生成，必须先调用 `Budget.check()`；只有检查通过才能发出请求，调用成功后必须调用 `Budget.charge()` 记账。
2. 所有 Agent 之间传递的数据必须是 `contracts.py` 中定义的类型。新增字段时，先修改契约及其测试，再修改生产者和消费者。
3. API Key 只能从环境变量读取，禁止写入代码、配置、示例、测试夹具、命令参数、远程 URL 或日志。
4. 每一次外部模型调用都必须向 `run.jsonl` 追加结构化记录，至少包含时间、Agent、模型、耗时、估算或实际花费、成功状态和错误摘要。日志必须脱敏。
5. `--dry-run` 不得发起网络请求、创建远程任务或产生费用；它只解析并校验配置，打印完整 DAG、缓存命中情况及逐步和总计预估费用。
6. 审片不通过时，具体的 `critique` 和 `fix_hint` 必须回灌到下一次生成；达到配置的重试上限后停止并交由人工处理，禁止无限重试。
7. 不引入重型编排框架。`orchestrator.py` 保持在 300 行以内，调度、断点续跑、重试和失败状态必须一眼可读。
8. 外部服务的模型 ID、接口字段、价格和地域要求可能变化；Provider 实现前必须核对官方文档，差异封装在 Provider 层，不得泄漏到 Agent 业务逻辑。

## 工程风格

- Python 3.11+，公开函数和数据边界全部写类型标注。
- 错误应抛出有上下文的异常，不吞错后返回 `None`。
- 注释解释“为什么”和约束来源，不复述代码表面行为。
- 网络、计费、轮询和 ffmpeg 边界必须可替换、可模拟并有测试。
- 不声称尚未实现、尚未运行或尚未验证的能力已经完成。
