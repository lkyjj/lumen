# LUMEN 架构说明

> 文档性质：人工整理的、可审查的目标架构，不是 Qoder 自动生成结果。
>
> 当前状态：运行时代码、离线测试、便携媒体管线和 ModelScope Studio 入口已落仓；真实 Provider 成片仍受锚点审批、Go/No-Go、有效凭据与付费确认门禁约束，不能把概念预告当作完整成片。

## 1. 系统目标

LUMEN 把电影生产拆为可调度、可审查、可重跑的工程系统。`film.yaml` 是电影源代码；八个剧组角色通过类型化契约生成脚本、分镜、锚点、片段、声音和成片，并以运行账本记录模型调用、审片结论和费用。

核心区别不是“调用多个模型”，而是审片 Agent 能依据导演意图和角色锚点评估素材，并将具体修正意见回灌给摄影环节；达到有限重试上限后交给人，而不是无限生成。

## 3. 目标组件

| 组件 | 职责 | 主要输入 | 主要输出 | 当前状态 |
|---|---|---|---|---|
| `producer` / `orchestrator` | DAG 调度、缓存、断点续跑、有限重试 | `film.yaml` | 运行状态 | 已实现；真实全片待门禁 |
| `screenwriter` | 将 logline 变为结构化剧本 | 电影设定 | `script.json` | 冻结作品适配器已实现 |
| `storyboarder` | 拆解可生成、可审片镜头 | 剧本 | `shots.json` | 冻结作品适配器已实现 |
| `art_director` | 生成并管理角色/场景锚点 | 角色与风格 | `bible/*.png` | Provider、版本与审批门已实现 |
| `cinematographer` | 以分镜和锚点生成片段 | `Shot`、锚点 | `clips/*.mp4` | I2V、缓存、有限重拍已实现 |
| `sound_designer` | 生成系统音、人声、音效和音乐 | 剧本、镜头表 | `audio/*.wav` | TTS 对白已实现；完整声音设计待成片 |
| `critic` | 四维评分并产生修正意见 | 片段、意图、锚点 | 审片结果 | 三帧 VLM 审片与本地裁决已实现 |
| `editor` | 合成画面、声音和字幕 | 已通过片段、音轨 | `final.mp4` | ffmpeg 合成与严格校验已实现 |
| `providers` | 隔离模型、HTTP、轮询和本地工具差异 | 类型化请求 | 类型化响应 | ModelScope、DashScope 与 Fake 已实现 |
| `budget` | 请求前硬熔断、成功后记账 | 估算费用 | 账本记录 | 已实现并有离线测试 |

## 4. 数据与控制边界

`lumen/contracts.py` 是所有 Agent 的共享骨架。Agent 不交换裸字典；外部服务响应只在 Provider 边界解析，并在进入下游前完成校验。

关键对象：

- `Shot`：镜头 ID、时长、景别、运镜、锚点、角色、场景、导演意图、prompt 种子和声音设计；
- `ShotResult`：素材路径、尝试次数、审片分数、意见、成本与通过状态；
- 运行事件：时间、运行 ID、Agent、模型、耗时、费用、状态和脱敏错误。

控制面由 `orchestrator`、`budget` 和质量门组成；数据面由 `film.yaml`、结构化 JSON、锚点、媒体文件及 `run.jsonl` 组成。

## 5. 不变量

1. **先检查预算，后付费调用；成功后记账。** 超过硬上限立即停止。
2. **锚点镜头强制 I2V。** `shot.anchor` 有值时不得降级为纯 T2V。
3. **接口代际隔离。** `wan3.x` 使用媒体数组，`wan2.x` 使用图像 URL 字段，差异只存在于视频 Provider。
4. **秘密不落仓。** 凭据仅从环境变量读取，日志与错误必须脱敏。
5. **dry-run 零外部副作用。** 不联网、不创建任务、不产生费用。
6. **失败可解释。** 审片意见必须具体，并进入下一次 prompt；有限重试后人工接管。
7. **人类创作关口不可跳过。** E-06 锚点定稿和试拍后的 Go / No-Go 由用户确认。

## 6. 可追溯产物

每次运行应能从 `run.jsonl` 追溯：输入配置、执行 DAG、各 Agent 与模型、镜头尝试次数、审片评分、修正意见、成本和最终选用素材。缓存或断点续跑不能抹掉先前尝试记录。

目标项目目录按阶段保存：剧本、镜头表、角色/场景 Bible、片段、声音、剪辑和最终成片。中间产物是审查证据，不只是临时文件。

## 7. 验证顺序

1. 契约和配置解析单元测试；
2. dry-run DAG 与费用估算测试，证明无网络访问；
3. Provider 模拟测试，包括超时、失败、轮询和脱敏；
4. 预算硬熔断与成功记账测试；
5. 单镜头端到端试拍及审片回灌；
6. 用户确认角色锚点和 Go / No-Go；
7. 批量生成、剪辑、成片与部署验收。

机器可验证证据由测试、`scripts/check_submission.py`、状态文件和脱敏账本给出；账号侧部署、真实生成质量与最终作品仍需创作者在人工门禁后验收。
