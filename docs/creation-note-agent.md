## 为什么不是一个大 Prompt

电影制作中的失败并不都属于同一种失败。剧本结构、景别、角色长相、时间稳定性、声音
和节奏需要不同的判断标准。LUMEN 因此把工作拆给八个角色：制片、编剧、分镜、美术、
摄影、声音、剪辑和审片。

角色不是八个名字不同的函数。每个角色只接收严格契约允许的数据；字段改变必须先改变
`contracts.py`。这样，错误会在边界失败，而不是在几次付费调用之后才暴露。

## film.yaml：电影的源代码

`film.yaml` 固化叙事、时长、锚点、预算、质量门和 14 镜。默认 frozen 模式不会让模型
覆盖手工校对过的镜头；显式再生成也必须保留 ID、顺序、总时长和引用关系。

## 审片闭环

每条素材在 25%、50%、75% 抽三帧，VLM 从角色一致性、构图、光线和崩坏四维评分。
程序不相信模型自己给出的 `passed`，而是重算平均分和单项底线。不通过时，具体问题和
可执行修正会前置到下一次 prompt；最多重试两次。

## 一个会自己停下来的系统

视频和图像 Provider 必须先向 `Budget` 申请额度。并发任务会先预留，失败释放，成功才
记账。达到 ¥300 时系统抛出异常并停止，而不是只打印一条容易被忽略的警告。

## 真实 Provider 与降级

ModelScope 负责文本/VLM；DashScope 负责图像、视频和 TTS。视频适配器按模型能力构造
payload：Wan 3.0 与 Wan 2.7 使用 `media[]`，旧 Wan 2.6 I2V 使用 `img_url`。Wan 3.0
无邀测权限时立即降级，不重复烧请求。

## Qoder 如何进入工程证据

`.qoder/rules` 固化预算、密钥、影视语言与 API 契约；`.qoder/agents` 定义四个可审查的
专家角色。仓库内的 repowiki 是人工维护的架构文档，明确不冒充 `/knowledge` 的自动产物。

## 局限

1. 可重放输入不等于像素级确定性。
2. 角色锚点和 D9 Go/No-Go 仍需创作者判断。
3. 免费推理没有生产 SLA，模型权限、地域、价格和配额必须在运行前重新核对。
